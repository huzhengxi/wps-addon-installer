# WPS 加载项安装器 UI 设计稿 v2

状态：**待产品审核，不进入开发**  
日期：2026-08-30  
适用平台：macOS、Windows 桌面端（Tauri）

## 1. 设计目标

把当前“只安装日期选择器”的单用途窗口升级为轻量的 WPS 插件管理器，让普通用户可以：

1. 查看可安装与已安装插件；
2. 从默认源或自定义源安装、更新、修复插件；
3. 选择一个或多个已安装插件并安全卸载；
4. 看懂 WPS 目录访问权限的当前状态，并在拒绝后恢复授权；
5. 在遇到问题时直接进入对应的用户手册章节。

首版仍保持“少设置、明确风险、操作可恢复”的产品气质，不做插件市场社区、账户、评分和推荐算法。

## 2. 控件源托管建议

### 推荐默认方案：GitHub Pages 索引 + GitHub Releases 文件

这是本项目当前最合适的默认源：现有安装器更新已经使用 GitHub Releases，可以复用发布账号、Actions 和版本流程；Pages 只托管很小的 JSON 索引，真正的 `.7z` 文件放在 Releases。

- 索引示例：`https://huzhengxi.github.io/wps-addon-catalog/v1/index.json`
- 文件示例：`https://github.com/huzhengxi/wps-addon-catalog/releases/download/date-picker-v1.0.1/date-picker-1.0.1.7z`
- 公共仓库可免费使用 GitHub Pages；GitHub Release 单个附件上限 2 GiB，每个 Release 最多 1000 个附件，官方文档说明 Release 总大小和带宽不限。
- 每个插件版本使用固定 tag 的不可变下载 URL，索引可以更新，但已发布版本的文件 URL 不变。

参考：[GitHub Pages 免费范围](https://docs.github.com/en/pages/getting-started-with-github-pages)、[GitHub Releases 配额](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

### 备用方案 A：Cloudflare R2

适合以后把默认源迁移到独立域名，或作为全球镜像。R2 当前标准存储免费额度为每月 10 GB、100 万次 Class A、1000 万次 Class B，并且直接从 R2 出网免费。建议绑定自有域名，不把 `r2.dev` 测试域名作为长期产品地址。

参考：[Cloudflare R2 价格与免费额度](https://developers.cloudflare.com/r2/pricing/)、[R2 自定义域名](https://developers.cloudflare.com/api/python/resources/r2/subresources/buckets/subresources/domains/subresources/custom/methods/create/)。

### 备用方案 B：Gitee Releases 镜像

适合作为中国大陆用户的可选镜像。Gitee 支持按 tag 的发行版附件下载 URL；免费仓库当前公开配额说明为单仓库 500 MB、单文件 50 MB，因此更适合作为小型控件包镜像，不作为唯一权威源。

参考：[Gitee 发行版下载 URL](https://blog.gitee.com/2022/08/18/update/)、[Gitee 免费仓库文件限制](https://gitee.com/help/articles/4232_)。

### 默认决策

- 首版默认源：GitHub Pages + GitHub Releases；
- 可选内地镜像：Gitee Releases，由用户手动添加或后续作为第二内置源；
- 中长期主源：如果下载量或大陆可用性成为问题，再迁移到 Cloudflare R2 自有域名；
- 不推荐把插件文件直接提交到 Git 历史，也不使用“latest”作为插件包下载地址；
- 默认源可以停用但不能删除，自定义源可以新增、编辑、停用和删除。

## 3. 控件源数据契约草案

用户填写的是“索引 URL”，不是文件夹或任意脚本地址。索引只描述静态文件，安装器不执行远程代码。

```json
{
  "schemaVersion": 1,
  "source": {
    "id": "official",
    "name": "官方控件源",
    "updatedAt": "2026-08-30T00:00:00Z"
  },
  "addons": [
    {
      "id": "date-picker",
      "name": "日期选择器",
      "type": "et",
      "version": "1.0.1",
      "platforms": ["macos", "windows"],
      "minimumWpsVersion": {
        "macos": "12.1.26055",
        "windows": "11.8.2.8808"
      },
      "downloadUrl": "https://github.com/example/wps-addon-catalog/releases/download/date-picker-v1.0.1/date-picker-1.0.1.7z",
      "sha256": "64-character-lowercase-hex",
      "size": 123456,
      "publishedAt": "2026-08-30T00:00:00Z",
      "releaseNotes": "首次在线源版本。"
    }
  ]
}
```

首版安全规则：只接受 HTTPS；拒绝重定向到非 HTTPS；限制索引与压缩包大小；下载后先校验 SHA-256 再解压；插件 ID、版本、根目录名使用白名单；禁止绝对路径、`..` 和符号链接逃逸。

## 4. 信息架构

窗口建议从固定 `620 × 620` 调整为默认 `920 × 680`、最小 `760 × 600`、允许缩放。主导航放在左侧，减少多模块之间的上下文丢失。

| 导航 | 用户问题 | 主要动作 |
|---|---|---|
| 插件 | 我有哪些插件，还能安装什么？ | 安装、更新、修复、卸载 |
| 控件源 | 插件从哪里来，源是否可用？ | 添加、编辑、测试、启停、刷新 |
| 权限 | 为什么无法访问 WPS，怎么恢复？ | 申请、重新检测、打开系统设置、选择目录 |
| 帮助 | 下一步怎么做，失败怎么办？ | 搜索手册、复制诊断、检查应用更新 |

窗口底部常驻显示 WPS 状态和当前安装器版本，但不抢占主操作层级。

## 5. 核心页面

### 5.1 插件页（默认首页）

页面顶部只保留一个搜索框和“刷新”按钮。内容用两段普通列表，不把每个插件做成大卡片。

#### 已安装

每行显示：复选框、图标、名称、版本、来源、健康状态、可用更新、更多菜单。选择后底部出现批量操作条：“已选择 N 项”“卸载”。

状态文案：

- 已安装：绿色圆点；
- 可更新：紫色“更新到 x.y.z”；
- 需要修复：橙色；
- 外部安装：中性标签，卸载前强调风险；
- 残留/损坏：红色，并提供“查看详情”“清理残留”。

#### 可安装

每行显示：图标、名称、简介、最新版本、来源和主按钮“安装”。日期选择器作为默认源的第一项。无网络时保留上次缓存，并显示缓存时间，不把整页替换成错误屏。

### 5.2 控件源页

顶部说明：“控件源提供插件列表和下载地址。只添加你信任的 HTTPS 地址。”右上角主按钮“添加控件源”。

源列表每行显示：名称、域名、默认/自定义标签、启用开关、最近同步时间、状态和更多菜单。默认源允许停用和测试，不允许删除。

“添加/编辑源”使用对话框：

- 名称；
- 索引 URL；
- 启用开关；
- “测试连接”次要按钮；
- 测试成功时显示源名称、插件数、更新时间；
- 保存前必须通过格式校验，连接失败时允许“仍然保存为停用”，不允许直接启用坏源。

多源同名插件默认按源优先级选择；首版优先级用拖拽或“上移/下移”调整，不自动选择更高版本的陌生源。

### 5.3 权限页

权限页不是技术日志，而是三项可理解的检查：

1. 找到 WPS Office；
2. 读取 WPS 版本与安装位置；
3. 读写当前用户的 WPS 加载项目录。

每项显示“已允许 / 需要授权 / 未找到 / 受系统策略限制”。页面只给一个当前最合适的主操作。

#### macOS

- 首次需要时：按钮“申请访问权限”；
- 用户拒绝后：显示“权限未开启”，主按钮改为“打开系统设置”，次按钮“重新检测”；
- 指引：系统设置 → 隐私与安全性 → 文件与文件夹；若系统没有列出可恢复的目录级权限或仍无法写入，再引导到“完全磁盘访问权限”；
- 提供“重新选择 WPS 目录”，通过系统目录选择器建立用户明确授权；
- 权限变更可能要求退出并重新打开安装器，界面必须明确说明。

Apple 官方说明可在“系统设置 → 隐私与安全性”管理文件与文件夹或完全磁盘访问权限：[文件与文件夹](https://support.apple.com/guide/mac-help/control-access-to-files-and-folders-on-mac-mchld5a35146/mac)、[隐私与安全设置](https://support.apple.com/en-gb/guide/mac-help/mchl211c911f/mac)。

#### Windows

- 普通用户目录写入失败时先提供“重新申请/重试”，不默认要求管理员权限；
- WPS 安装目录只读探测失败时提供“选择 WPS 安装目录”；
- 如果被 Windows 安全中心“受控文件夹访问”拦截，展示打开 Windows 安全中心的步骤；
- 只有后端明确返回需要提升权限时，才显示“以管理员身份重新打开”。

参考：[Windows 文件系统访问设置](https://support.microsoft.com/en-US/Windows/privacy/windows-file-system-access-and-privacy)、[受控文件夹访问](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/virus-and-threat-protection-in-the-windows-security-app)。

### 5.4 帮助页

顶部是搜索框，下面按任务而不是按技术模块组织：

- 快速开始；
- 安装、更新与修复插件；
- 查看和卸载插件；
- 添加自定义控件源；
- macOS 权限恢复；
- Windows 权限恢复；
- 常见错误与诊断；
- 发布控件包（维护者）。

底部保留“复制诊断信息”“打开日志目录”“检查应用更新”。诊断信息复制前显示脱敏说明。

## 6. 关键交互流程

### 首次安装日期选择器

`启动检查 → 默认源同步 → 插件页看到日期选择器 → 安装 → 权限不足时进入权限引导 → 下载 → 校验 → 安装 → 提示保存文档 → 重启 WPS → 成功`

下载与安装分为清晰阶段：连接源、下载、验证完整性、部署、重启 WPS。用户可以在下载阶段取消；进入部署后不可取消，避免半安装状态。

### 批量卸载

`勾选插件 → 底部批量操作条 → 卸载 → 确认对话框列出名称和影响 → 结构化移除对应 publish.xml 条目 → 重启 WPS → 刷新列表`

确认框默认焦点在“取消”；外部安装或损坏插件需要额外说明，但不要求用户输入插件名。

### 用户拒绝权限后的恢复

`操作失败并识别为权限拒绝 → 就地提示“权限未开启” → 查看权限 → 打开系统设置/重新选择目录 → 返回应用 → 重新检测 → 自动继续原操作（需再次确认 WPS 重启）`

应用要记住“待恢复操作”，但不能在用户返回后静默安装或卸载。

## 7. 通用状态与文案

- 空状态：解释为什么为空，并给一个动作，例如“还没有已安装插件” + “查看可安装插件”；
- 无网络：显示上次缓存时间 + “重试”，已安装插件仍可查看和卸载；
- 源不可用：只标记对应源，不阻塞其他源；
- 校验失败：“下载的文件与发布者提供的校验值不一致，已删除该文件”，不提供忽略校验；
- WPS 正在运行：安装前才提示保存文档，浏览列表时不打扰；
- 成功：短暂提示并更新列表，不弹阻塞式成功对话框；
- 危险操作：卸载用红色文本按钮，只有确认弹窗中的最终动作用红色实心按钮。

## 8. 视觉方向与无障碍

沿用当前界面的深色/浅色自适应、紫色品牌色和系统中文字体。降低“大卡片套大卡片”的使用，以列表、留白和分隔线建立层级。

- 主色：沿用 `#6954DB`；
- 成功：`#147A3C`；警告：`#9A5500`；危险：`#B42318`；
- 正文默认 14–15 px，辅助信息不低于 12 px；
- 所有图标配文本或可访问名称，不以颜色作为唯一状态；
- 键盘可遍历导航、列表选择、菜单、对话框和进度操作；
- 对话框打开后锁定焦点，关闭后回到触发按钮；
- 尊重系统减少动态效果，下载进度使用 `aria-live` 的阶段文案；
- 复选框批量操作提供“全选当前列表”，不隐藏在右键菜单。

## 9. 用户手册交付结构

开发阶段新增 `docs/user-guide/`，采用 Markdown 作为唯一内容源，同时生成应用内离线帮助和仓库文档：

```text
docs/user-guide/
├── index.md
├── quick-start.md
├── manage-addons.md
├── custom-sources.md
├── permissions-macos.md
├── permissions-windows.md
├── troubleshooting.md
└── maintainer-publishing.md
```

每一章固定包含：适用场景、操作步骤、预期结果、失败时怎么办。权限章节在目标系统实机截图后再定稿，避免使用过时或不匹配的系统设置截图。

## 10. 开发交接边界

UI 审核通过前不修改 `index.html`、`src/main.ts`、`src/styles.css`、Rust command、Tauri 权限或资源打包配置。开发模型实施时应先更新架构与数据模型，再按“控件源 → 权限检测 → 插件发现 → 安装/卸载 → 手册”的顺序完成，不在前端暴露任意路径删除或远程脚本执行能力。
